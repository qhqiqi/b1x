# docs/ · P1 的领地

P1（队长 / 产品 & 路演）在这里放：一页纸、PPT 大纲、Demo 剧本、Q&A 弹药库、评审锚点对照表。

## 开工第一件事（10 分钟，别先做 PPT）

1. 读 `data/reports/p1_one_pager.md` —— **答辩口径全在里面**：哪些数字能说、哪些绝对不能说、5 个高频追问的标准答案。数字都有出处，别自己另算。
2. 读 `data/reports/test_report_gap.md` 第五节 —— 测试报告拿不到时怎么接话（两个版本，选一个）。
3. 填 `交接/P1.md` 第 2 节那 4 个待决问题。**P2 和 P3 都卡在这上面**：
   - PPT 用"测试报告溯源"还是"产品册页码溯源"
   - 报价口径（建议：询价确认）
   - 演示优先核哪几条车桥/车型
   - 19:30 链路跑不通砍到什么范围
4. 决定写进 `进度看板.md` 第 4 节（决策日志），然后当面告诉 P2/P3。

## 目录约定

| 目录 | 放什么 |
|---|---|
| `docs/` | 一页纸、大纲、剧本、Q&A（markdown，能直接读） |
| `ppt/` | 演示文件（.pptx / .key / 导出的 PDF） |
| `交付/` | 最终要交出去的东西：报名材料、截图、录屏 |

## 两条硬规矩

1. **大于 20MB 的文件别提交**（录屏、原始 pptx 素材）：放 `交付/` 之外的本地目录，或者只提交导出的 PDF。仓库大了每个人同步都变慢。
2. **数字只用 `p1_one_pager.md` 里那些**：217 条 SKU / 127 条文字层逐条复核 / 17 条扫描页抽检 / 42/42 演示路径全核 / 34 条出口对码（10 条核过）/ 8/8 海外对码 / 20-20、10-10、12-12 三份评测 / 3–6 ms。**说错一个数字比说错一句话更致命。**
